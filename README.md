# 车辆检测与标签质量治理

这个项目关注道路场景中四类车辆检测的训练标签质量，覆盖卡车、汽车、厢式车和公交车。基于 3LC Multi Vehicle Detection Challenge 数据，固定 YOLOv8n 并从随机初始化训练。排查跨集合重复图像后，按视频场景和精确图像哈希做五折分组，用折外预测筛查疑似漏框与错类。经审核确认的修订写入独立的标签版本，保留原始数据。

| 标签版本 | mAP@0.5 | mAP@0.5:0.95 |

两组均使用相同的 7,852 张训练图、YOLOv8n、640 像素输入和 28 轮训练设置，在同一组 966 张开发验证图上统一终评。表中最佳版本按 mAP@0.5 选取。 [本地指标明细](reports/metrics.csv)

## 数据清洗方法

1. **筛查相似帧，降低验证泄漏风险。** 用感知哈希 dHash 查找跨训练集和验证集的近重复候选，再用 SHA256 和解码像素确认完全重复。取用验证集时排除确认重复的 16 张图，形成固定的 966 张开发验证图（val966）。
2. **用分组五折 OOF 定位疑似错漏标。** 按视频场景和图像哈希分组，7,852 张训练图各预测一次，负责预测的模型训练时没有使用该图及同组图。疑似漏标要求预测框与任一原框的最大 IoU 小于 0.10，且被任一原框覆盖的面积比例小于 20%。疑似错类要求预测与异类原框的 IoU 至少为 0.70，且与所有同类原框的最大 IoU 小于 0.30。
3. **先人工抽查候选，再扩大范围。** 我从置信度 ≥ 0.90 的候选中按类型和场景定向抽查了 30 项，覆盖 27 个场景。疑似漏标确认 **11/12**，疑似错类确认 **7/18**。合计确认 **18/30（60%）**。其余有 10 项是模型误判、1 项无需标注、1 项目标对应待确认。这一命中比例只描述本次高置信抽样。
4. **用视觉 Agent 分批补框和改类。** 单人难以逐一排查数千条候选，我让 Agent 在原图上对照原标签和 OOF 候选框。首轮审核置信度 ≥ 0.85 的 744 条候选。扩展阶段依次降低门槛至 0.80、0.70 和 0.60，再审核 6,188 条新增候选，每批最多 12 条。预测框用来定位，Agent 看图确认是否补框及最终边界，改类沿用原框坐标。每条记录候选 ID、原图证据、类别、坐标和判断理由。图像看不清、类别边界模糊或目标对应不明时，保留意见供人工复核，暂缓项保留原标签。
5. **抽查视觉质量并校验写入。** 扩展阶段按补框、改类、保留和暂缓抽看 20 张原图及对应意见，人工判定整体大体合理。这轮抽查只记录整体判断，未统计全量标注错误率。汇总时用原图哈希和候选 ID 拦住串图、串框，校验类别、坐标和重复补框，排除 124 条冲突候选。批准后的提案应用到独立副本，再逐行重算补框、改类和框总数，核对原始图像及固定验证标签的字节一致性。

相对原始标签 D0，本地最佳清洗版 D070 **补框 1,807 个、改类 184 处**。清洗范围最大的 D060 **补框 3,361 个、改类 274 处**，涉及 7,852 个训练标签文件中的 **2,207 个**。 [实验与复查](reports/results.md#数据审计和标签修订)

## 快速运行

用合成标签和模拟折外预测演示候选筛选、审核与标签应用。示例只需 CPU 和 NumPy，无需下载模型或赛事数据。

已在 Windows、Python 3.13.5 和 NumPy 2.4.6 验证以下命令。请在仓库根目录运行。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B -m examples.label_review
.\.venv\Scripts\python.exe -B -m unittest discover -s tests
```

示例应找到 3 条候选，应用 1 处改类和 1 个补框，按示例审核决定保留其余 1 条。输出写入 `demo-output/revised.txt`，原 `examples/sample.txt` 保持字节一致。再次运行时，通过 `--output` 指定一个新目录。合成回归覆盖候选匹配、审批校验、标签副本及结果验证。
